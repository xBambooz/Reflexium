# Iris and Vulkan status, 2026-10-15

## Decision

**No: Iris cannot replace Vitrail in Reflexium today.** The current released Iris build for this project's target, `1.11.7+mc26.3-fabric` from 2026-09-30, is an OpenGL shader loader. It requires Sodium `0.9.x` and contains OpenGL-only execution paths. It is not compatible with Minecraft 26.3's native RenderPearl Vulkan backend. Do not remove, disable, or migrate from the existing Vitrail integration on the basis of an Iris update.

This is not the old, unrelated VulkanMod incompatibility. It is specifically Minecraft's built-in Vulkan backend. Iris issue [#3357](https://github.com/IrisShaders/Iris/issues/3357) records Iris `1.11.6+26.3-fabric` aborting under `--graphicsBackend vulkan` because it calls OpenGL with no current GL context. The later `1.11.7` release's stated changelog is only "Fixes a lot of 26.3 bugs" and does not announce Vulkan support. Its downloadable JAR still has `net.irisshaders.iris.gl.IrisRenderSystem`, `SamplerLimits`, LWJGL `org.lwjgl.opengl.*` calls, and a cast to RenderPearl's OpenGL `GlDevice`, verified by `javap` on the artifact below.

The likely source of the report is **Aperture**, a separate future Vulkan shader loader by the Iris team, not a new Iris backend. The public Iris repository has no released Aperture artifact, no public Aperture branch, no compatibility matrix, and no implementation entry point that Reflexium can target. The public request for its release remains open without a maintainer answer: [Iris issue #3279](https://github.com/IrisShaders/Iris/issues/3279). Treat it as announced/private-beta work, not preview or usable release.

## Primary evidence and artifact inspection

1. [Official Iris Modrinth 1.11.7 artifact](https://cdn.modrinth.com/data/YL57xq9U/versions/vTN4NRGW/iris-fabric-1.11.7%2Bmc26.3.jar): version `1.11.7+26.3-fabric`, Fabric 26.3, published 2026-09-30 02:57 UTC. Its `fabric.mod.json` declares `sodium: ["0.9.x"]` as a required dependency and `LGPL-3.0-only`.
2. Local read-only artifact inspection of that exact JAR produced the Modrinth-published SHA-512 above. `javap -c` shows `IrisRenderSystem.initRenderer()` calling `org.lwjgl.opengl.GL.getCapabilities()`, and its static initialization reaches `SamplerLimits.get()`. `IrisRenderSystem.getGlDevice()` casts the RenderPearl backend to `com.mojang.renderpearl.backend.opengl.GlDevice`. This is direct executable evidence, not an inference from its name or old documentation.
3. Iris's own source retains the same OpenGL boundary in [`IrisRenderSystem.java` on branch 26.3](https://github.com/IrisShaders/Iris/blob/26.3/common/src/main/java/net/irisshaders/iris/gl/IrisRenderSystem.java). Its active 26.3 branch history through 2026-10-08 contains no Vulkan backend feature or release artifact.
4. [Issue #3357](https://github.com/IrisShaders/Iris/issues/3357) is a reproducible 26.3 native-Vulkan crash report with Iris 1.11.6 and Sodium 0.9.2. It shows the GL-context failure at Iris `SamplerLimits` / `IrisRenderSystem`. [Issue #3416](https://github.com/IrisShaders/Iris/issues/3416), opened 2026-10-12, still asks Iris to add native Vulkan support and remains open. These are direct official-repository evidence that it is not shipped support.
5. The Iris source repository's [branches](https://github.com/IrisShaders/Iris/branches) include `26.3` but no `aperture` branch. The repository's [releases](https://github.com/IrisShaders/Iris/releases) have no current 26.x GitHub release, so Modrinth is the actual 26.3 release channel inspected here.
6. Vitrail's own [project rationale](https://github.com/avpbynf/vitrail-shaders/blob/main/docs/why.md) distinguishes Iris as OpenGL and Aperture as a clean-break Slang engine, rather than an Iris update that continues running existing packs. This corroborates the boundary but is not used as proof of an Aperture release.

## Reflexium migration implications

The following is source/document review, not a request to implement it now. Current code is deliberately Vitrail-specific and runtime guarded.

| Concern | Current Vitrail-owned contract | What a real Iris/Aperture replacement would have to prove |
| --- | --- | --- |
| Render scale and upscaling insertion | `VitrailCompat` plus `RenderScaleMixin` give Reflexium sole render scale while a pack runs. The pack runs at the reduced target, then DLSS/FSR returns to display resolution before GUI. | Equivalent supported control over the pack render targets and a stable post-pack or, preferably, early linear-HDR insertion point. Iris 1.11.7 supplies only an incompatible OpenGL pipeline. |
| HDR | The active worktree contains `ComplementaryHdr` and `UpscalingRenderer` `RGBA16_FLOAT` input/output for a reviewed Complementary path. Historical docs still correctly say early HDR stage separation is a validation risk. | A documented HDR color attachment, transfer/tone-map ownership, exposure rules, and actual Vulkan image layouts. No Aperture artifact/API exposes these. |
| Jitter and TAA ownership | `GameRendererMixin` / `UpscalingRenderer` own Halton jitter. `VitrailCompat` forces Complementary r5.9.3 `TAA_JITTER=0`, retains its effect sampling, and `ComplementaryTemporalSource` bypasses only the pinned final `DoTAA` source hash. | A single, documented temporal owner. The replacement must expose projection and previous-projection timing and must not stack its TAA with DLSS/FSR. A new shader language means the current exact-source edits do not transfer. |
| Depth and motion | `GameRendererMixin` captures world depth and renders motion. The Vitrail mixins preserve pack/hand matrices; Reflexium combines world and hand depth, camera vectors, opaque object vectors, and has known gaps for transparent and shader-deformed surfaces. | Attachment lifetimes/formats, previous transforms for every relevant draw, and verified vector convention. No generic "Vulkan compatible" claim covers this. |
| Frame generation final color | `FrameGenerationRenderer.sceneReady` consumes the final upscaled scene plus depth and motion through Reflexium's existing RenderPearl Vulkan/NGX/FSR route. | A replacement must leave Reflexium the final color at the correct pre-GUI, pre-present stage and must preserve its queue/submission/present hooks. No Iris Vulkan integration exists to validate that handoff. |
| Pinned Complementary support | Current product support is specifically Complementary Reimagined r5.9.3, Vitrail 0.12.x, Sodium 0.9.2, with source hashes and a runnable compatibility check. | Rebuild pack support from the new engine's actual language/format and release. Aperture's reported non-OptiFine format means Complementary r5.9.3 cannot be assumed compatible. |

Current concrete integration entry points are [`VitrailCompat.java`](../../src/client/java/com/bambooz/reflexium/compat/VitrailCompat.java), [`ComplementaryTemporalSource.java`](../../src/client/java/com/bambooz/reflexium/compat/ComplementaryTemporalSource.java), [`reflexium.vitrail.mixins.json`](../../src/client/resources/reflexium.vitrail.mixins.json), [`GameRendererMixin.java`](../../src/client/java/com/bambooz/reflexium/mixin/GameRendererMixin.java), [`UpscalingRenderer.java`](../../src/client/java/com/bambooz/reflexium/dlss/UpscalingRenderer.java), and [`FrameGenerationRenderer.java`](../../src/client/java/com/bambooz/reflexium/dlss/FrameGenerationRenderer.java). The compatibility plugin only admits reviewed Vitrail 0.12.x hooks. There is no analogous Iris or Aperture adapter in the tree.

## Recommendation and blockers

1. Keep Vitrail as the only native-Vulkan shader-pack integration for Reflexium 26.3. Do not add Iris to the Vulkan profile and do not retire the Vitrail mixins.
2. If the desired change was actually "try the new Iris 1.11.7", it can only be evaluated on Minecraft's OpenGL backend. That is a separate rendering route and would not exercise Reflexium's Vulkan DLSS/FSR/FG integration.
3. Re-open this decision only after an official Aperture or Iris Vulkan release exposes all of: downloadable Fabric 26.3 artifact, licence, RenderPearl Vulkan support statement, stable source/API, pack-language and Complementary compatibility matrix, Sodium requirement, and attachment/timing hooks sufficient for the six contracts above.
4. Even then, create a separate optional adapter and retain Vitrail until a pinned, visual and lifecycle-validated migration passes. No performance campaign is justified by this research result.

### What remains uncertain

- Iris-team private-beta progress, roadmap and final Aperture licensing are not publicly verifiable from official downloadable artifacts.
- Whether any future Aperture release will support Complementary or any existing OptiFine-format pack is unknown. Current available evidence points the other way, so it must not be assumed.
- Iris 1.11.7 may fix 26.3 OpenGL regressions introduced in 1.11.6, but no official source claims it fixes the native-Vulkan GL-context incompatibility and the released artifact retains the same architectural dependency.
