# Round 16: Ryan's Fabric 26.3 profile benchmark

Date: 2026-10-25. Branch `round6-validation`, head `354e89b`.
Test profile: a full copy of `Fabric 26.3` named `Fabric 26.3 RxBench`, plus a minimal
copy named `Fabric 26.3 RxBench Min`. Ryan's real profile was never launched or modified.

## What was measured

Benchmark Mod route `benchmark-route`, 2560x1440, Minecraft 26.3 Vulkan, Iris
1.12.0-snapshot local, Reflexium 1.2.0-alpha (SHA-256 `B6F7DFB8...C709`), render distance 8,
maxFps 260 (unlimited), no VSync, particles all, Distant Horizons 3.3.5 where noted.
Benchmark Mod 1.0.0 wrote one measured pass per capture. Settings: warmup 8 s, one measured
run, no conditioning pass, GPU sampling off. The first capture after a mode or world change
was treated as conditioning and excluded from the accepted pair.

VM flags match the real session's log: `-Xmx12288M -XX:+UseShenandoahGC -Xss4M`,
`--enable-native-access=ALL-UNNAMED`, the Modrinth native paths and the add-opens list. The
Modrinth `theseus.jar` agent and IPC arguments were not used. The launch script was
`tools/launch-modrinth-profile.ps1` with a generated args file pointing at the copy.

Rows A and B were unfocused because a focused startup with DH present crashed repeatedly.
Rows C and D are focused on the secondary monitor, with the previous foreground restored
after each batch. Benchmark Mod reports `focusLost` from `Window.isFocused()`. A unfocused
runs still reported false, while the harness status showed `os_input_focus: false`, so the
flag is not a reliable focus proof. The A rows are used only for the relative comparison.

## Why DLSS loses

The 1440p route is CPU and vertex bound, not pixel bound, at these settings. Per-frame
timings from Reflexium's profiler, 12 s of the route, profiling on:

| Span | Native CPU us | Native GPU us | DLSS Quality CPU us | DLSS Quality GPU us |
| --- | --- | --- | --- | --- |
| world including upscaling | 2356 | 1255 | 3135 | 1889 |
| terrain solid | 499 | 578 | 513 | 478 |
| iris deferred | 15 | 166 | 16 | 76 |
| iris composite | 67 | 129 | 76 | 100 |
| iris final | 16 | 84 | 16 | 45 |
| DLSS evaluate | 0 | 0 | 85 | 932 |
| submit fence wait | 197 | 0 | 293 | 0 |
| present | 98 | 0 | 102 | 0 |

Rendering at 1707x960 saves about 0.26 ms of GPU work across terrain, deferred, composite
and final. The DLSS evaluation costs 0.93 ms GPU and 0.09 ms CPU, so the GPU frame grows by
0.63 ms. The CPU world span grows by 0.78 ms. Named spans explain only about 0.21 ms of that
increase. The remaining 0.56 ms is not covered by any span. It lies in the unmeasured parts
of the upscaling frame, including Streamline tags and constants, Vulkan interop downcalls,
barriers, `updateGlobals` and `resolveDisplayDepth`.

The fixed cost explains every row. At 979 native FPS the frame is 1.02 ms, so a 0.9 ms
evaluate caps DLSS near 516 FPS, exactly what D Mellow measures. DH does not cause it:
removing DH raises native from about 359 to 665 FPS and deepens the relative loss from 24 to
43 percent because the scene becomes even less pixel bound. With BSL the native frame is
3.79 ms and Performance renders at 1280x720, which saves enough pixel work to net +3.8
percent. Quality at 1707x960 saves less and lands 2.5 percent below native.

This is not a mod conflict. The minimal D set contains only Fabric API, Sodium, Iris,
Reflexium and Benchmark Mod, and it still loses 47 to 51 percent with Mellow. The loss is
larger in the minimal set because the frame rate is higher. There is no extra pack to
bisect.

## ObjectMotion slow path

The Sodium warning appears on the first DLSS frame:
`Class com.bambooz.reflexium.motion.ObjectMotion$Capture does not support optimized vertex writing code paths`.
It is real, but its cost is in the frame-time tail, not the average. In setup A, DLSS
Quality with object motion on measured 273.6 / 269.0 FPS and 1% lows of 148.5 / 115.2. With
`object_motion=0` it measured 271.9 FPS and a 1% low of 172.0, so the average is unchanged
and the low improves by 16 to 49 percent depending on the comparison run. The profiler's
own `object_motion` span is 0.8 us; the cost is inside entity and block-entity submission
through the generic BufferBuilder path.

A proper fix needs its own round. The two candidates are a static-track skip that stops
wrapping submits after one static frame, or an optimized vertex writer. The first risks
one frame of object vectors when an object starts moving.

## Minimal set and the shader-pack threshold

D is the discriminating set. With Mellow, native is 976 FPS and every DLSS mode loses about
half the frame rate. With BSL, native is 264 FPS and DLSS Performance wins by 3.8 percent
while Quality is 2.5 percent behind. The crossover follows the fixed cost, not a particular
mod: a heavier pack lowers native FPS and increases the pixel work that DLSS can remove.

## Startup crash found while testing

Direct launches of the copy crashed at the resource-reload step, right after
`Created: 2048x1024x0 minecraft:textures/atlas/gui.png-atlas`, in 15 application-error
events between 04:31 and 05:45. Twelve were in `jvm.dll`; seven shared the exact offset
`0xa88377`. Three were in an unknown module. No `hs_err_pid*.log` was written. The same
crash occurred focused and unfocused, with and without the harness, with DH on and off, and
with shaders on and off. A saved `upscaler=dlss` in `config/reflexium.properties` crashed 3
of 3 times; launching native and switching to DLSS after the title screen was the stable
workaround. Native launches also crashed intermittently (5 of about 10). The real profile
launched by Modrinth stayed stable and was not touched.

The copies always contained the harness and BM driver jars, including the launches without
the harness active. That is a confound. This is not attributed to Reflexium. The
upscaler-at-startup case is the reproducible lead and should be tested with a clean copy
before any code change.

## Recommended fixes

1. Guide the user away from DLSS in very high-FPS light scenes. The in-game note should
   recommend native or Off when native is above roughly 300 FPS with a light pack such as
   Mellow, and recommend Performance when a heavy pack is used at 1440p. This matches the
   2026-10-24 decision log and does not add an auto probe.
2. Scope the 0.56 ms unattributed CPU in the DLSS world path. Start with the Streamline tag
   and constants block, the barrier pair around evaluation, `VulkanInterop` image calls and
   `resolveDisplayDepth`, then remove redundant work and re-measure with Benchmark Mod.
   Even a perfect CPU reduction leaves the 0.93 ms evaluate, so this narrows the gap but
   cannot make DLSS win at 979 FPS with Mellow.
3. Fix the ObjectMotion capture for static entity and block-entity submits, or use an
   optimized vertex writer. This targets 1% lows, not average FPS.
4. Defer the DLSS feature build until a world exists and guard the resource-reload
   transition. Reproduce the startup crash with a clean copy, then fix and re-measure.
5. Do not switch the default model to CNN on this evidence. AUTO already passes preset 11,
   and CNN would trade image quality for a cost reduction that still cannot beat native in
   the Mellow scene.

No code was changed or rebuilt in this round. The headline loss comes from the fixed DLSS
evaluation cost plus a scene that is not pixel bound, not from a Reflexium regression. The
actionable Reflexium overhead is measured and listed above for the next round. A speculative
change to chase 25 percent would violate the no band-aid rule.

## Validity and limits

- Window 2560x1440 on the XF250Q secondary display, swapchain 2560x1440, IMMEDIATE present,
  no VSync. The window covered the display and spilled off its physical 1920x1080 panel.
- Mode proof: Reflexium status and log show 1707x960 for Quality, 1280x720 for Performance,
  `upscaler_effective=dlss`, the pack name and `Reflexium jitter`. Native rows show
  `upscaler_effective=off` and render size equal to display size.
- Content proof: `rx16-dlssq-mid-640.png` is a mid-route crop from the DLSS Quality run with
  Mellow, showing the pack's water color, foliage and Distant Horizons LODs.
- Benchmark Mod records `renderer.shadersEnabled=false` on Vulkan because its Iris check
  requires the OpenGL backend. Do not use that field as shader proof in this environment.
- Render distance is 8, Ryan's setting. The scene hint is 16, so Benchmark Mod flags
  `renderDistanceMismatch`.
- A was unfocused. Focused C native is 665 FPS against 714 unfocused, about 7 percent lower,
  so focused A would be slower in absolute terms. The DLSS deficit is not a focus artifact:
  every focused C and D row shows the same direction and a larger relative loss.
- On the DH route the 1% low is not repeatable within 3 percent for A Quality, A Performance
  and C Quality. The table shows the raw pair and marks those rows. Every accepted average
  is inside 3 percent.
- The first A native run (321.9 FPS, 1% low 30.9) and the first A Performance run (238.4)
  were cold DH or terrain captures and were excluded. C and D run 0 were conditioning.
- A focused A row was not obtained: focused startup with DH present crashed every attempt.
