# Round 8: Streamline SR with DLSS-G, Reflex cost, BSL shadows and WGC, 2026-10-24

This round makes Streamline DLSS SR the default path when DLSS-G is on, verifies generated
presents with SR on the same constants block, measures the Reflex cost at CPU-bound and extreme
rates, profiles the BSL 1440p shadow claim, and adds a Windows Graphics Capture tool for presented
frames. Every FPS row follows the [OBJECTIVES.md](../OBJECTIVES.md) validity rules.

## Environment and method

- Windows 11, RTX 5070 12 GB, NVIDIA 617.42, GraalVM Java 25.0.4, Minecraft 26.3, Vulkan.
- Streamline 2.14.16, BSL v10.1.8, Iris `1.12.0-snapshot+mc26.3-local`, Sodium 0.9.2.
- Harness window 1920x1080 or 2560x1440 on the secondary XF250Q 240 Hz display, focused with
  `-Activate`. Render distance 31, simulation distance 12, Max Framerate 260 (Unlimited), VSync off.
- Range pose (200.5, 151, 0.5, yaw 0, pitch 3). Forest pose (200.5, 67, 150, yaw 90).
  Samples are 5 second render-frame deltas after at least 9 seconds of settling; repeats are shown.
- The black OLED-care overlay covered both monitors for the round. Render-target and WGC captures
  still return content.

## 1. What changed

- `StreamlineSupport.beginFrame(int, boolean)` now uses the caller's frame number. `ReflexController`
  increments one `frameId`, creates the Streamline token with that number, and chains the same number
  in `VkPresentIdKHR`. The token, common constants, PCL markers and present id no longer drift by one.
- `UpscalingRenderer` runs DLSS SR on Streamline whenever DLSS-G is requested. The shared path sets
  one constants block in `streamlineSceneReady` before `slDLSSGSetOptions`, then evaluates SR on the
  mirrored inputs and mirrors the display-size result back. Loading/menu frames run Streamline SR
  alone on the scene orientation instead of falling into the uncreated raw NGX feature.
- The `-Dreflexium.sr.fgStreamline` gate is gone from the product path.
- `native/reflexium_sl.cpp` no longer queries `slDLSSGGetState` during device registration; the read
  is present-thread only and returned a stale status before Reflex existed.
- The committed `reflexium_sl.dll` was stale and missed `rx_sl_pcl_stats_message`, which made the
  previous "final path" run fall back to raw NGX. The bridge was rebuilt and the export is present.
- `tools/wgc-capture` is a small .NET 10 WGC tool. It captures a window by pid or HWND, writes
  `frames.csv`, and optionally saves cropped PNGs. `MinUpdateInterval = 0` raises the delivery rate
  from 60 Hz to the 240 Hz display rate; `--png false` keeps the 240 Hz timing path.

## 2. Streamline SR and DLSS-G together

BSL 1080p range, DLSS Performance, 2x, focused client. `evaluated_frames` and
`generated_presents` are lifetime counters:

| Window | Real frames | Generated frames | Ratio |
| --- | ---: | ---: | ---: |
| 5 s | 1,418 | 707 | 0.499 |
| 12 s | 5,198 | 2,597 | 0.500 |

The counters rise together, the SR evaluate counter rises with them, and the generated presents
stop when frame generation is turned off. The control run with DLSS SR off reported DLSS-G status 0
and 403 generated frames for 404 real frames. With Streamline SR on the same frame, DLSS-G reports
status 2 (`eFailReflexNotDetectedAtRuntime`) while still generating exactly one frame per real
frame. The SDK log shows a one-frame mismatch, for example `52597 != 52598`, once per present. The
generation gate therefore treats bit 1 as non-fatal while Reflex is sleeping, and every other
status bit still disables frame generation.

Fixed 2x was never refresh-capped. The generated ratio is 1.0 per real frame, not the Auto
refresh-headroom result.

## 3. Reflex cost

All rows have Reflex markers and one `slReflexSleep` per rendered frame. No extra queue submit or
wait was added by the present-id path. The profile below is the mean for 1,469 frames:

| Span | CPU mean |
| --- | ---: |
| `reflex_sleep` | 878.5 us |
| `submit_including_wait` | 400.7 us |
| `world_including_upscaling` | 1,817 us |
| `evaluate` | 73.5 us CPU, 263.8 us GPU |

Shaderless 1080p native, render distance 31:

| Reflex | FPS sample 1 | FPS sample 2 | Render latency |
| --- | ---: | ---: | ---: |
| Off | 1,442.0 | 1,437.8 | 1.1 to 1.4 ms |
| On | 1,356.8 | 1,369.6 | 1.2 ms |
| On + Boost | 1,360.9 | - | 1.2 ms |

BSL 1080p range, DLSS Performance, 1x:

| Reflex | FPS sample 1 | FPS sample 2 | Render latency |
| --- | ---: | ---: | ---: |
| Off | 321.2 | 320.5 | 6.2 to 6.4 ms |
| On | 298.2 | 294.3 | 4.8 to 4.9 ms |
| On + Boost | 296.2 | - | 6.0 ms |

The cost is the driver sleep, not a Reflexium pass. It is below the 4% NVIDIA reference at 1,400
FPS only in the best sample, and above it at 300 FPS. The objective is not met on this driver.

## 4. Objective 1 and the BSL shadow claim

BSL 1080p range, frame generation off, Reflex On:

| Mode | FPS rep 1 | FPS rep 2 | Delta |
| --- | ---: | ---: | ---: |
| Native | 299.3 | 300.1 | - |
| Quality | 280.1 | 281.8 | -6.4% |
| Balanced | 283.7 | 284.3 | -5.4% |
| Performance | 305.6 | 306.0 | +2.0% |

BSL 1440p range native: 267.6 and 267.0 FPS. The DLSS 1440p rows were not completed because the
runtime upscaler switch crashed in section 6.

Forest pose, GPU timestamps in microseconds:

| Row | World | Shadow | Terrain | Composite | Evaluate |
| --- | ---: | ---: | ---: | ---: | ---: |
| Native 2560x1440 | 3,419 | 1,016 | 834 | 708 | 0 |
| Native 1707x960 | 3,346 | 982 | 1,409 | 440 | 0 |
| DLSS Q 1440p (1707x960) | 3,979 | 884 | 1,582 | 375 | 428 |

The shadow pass is **not** more expensive under DLSS. At the same render size it is 884 us against
982 us native, and the native 1440p shadow pass is also near 1 ms. The earlier `SHADOW=false`
result removed the loss because it removed about 2 ms of shadow work and moved the scene from
GPU-bound to CPU-bound, where the 0.43 ms evaluate hides. The remaining loss is the DLSS evaluate
plus terrain GPU work, not a Reflexium pass and not a jitter or sampler leak into the shadow map.

## 5. Presented-frame capture with WGC

`tools/wgc-capture` built with .NET 10 and the Windows SDK projections. With
`session.MinUpdateInterval = 0`, the capture delivered 200 frames at a 4.17 ms median interval
(240 Hz) from the focused 1920x1080 window while Minecraft rendered at about 300 real FPS with
2x generation. PNG saving blocks the callback, so image runs use `--every` or a crop; timing runs
use `--png false`.

A 90 degree pan at BSL 1080p range, DLSS Performance, 2x, produced 120 captured frames. The two
960x540 crops in `round8-2026-10-24/wgc-pan-00002.png` and `wgc-pan-00004.png` show smooth
translation, a sharp crosshair and no doubling or ghost trail on the gate bars. The SDK still does
not expose which presented frames are generated, so this is visual evidence of the presented
stream, not a per-frame generated-image label.

## 6. Transition crash and remaining gaps

The in-world 1080p upscaler toggle between native and DLSS is stable after the transition guard:
one to four toggles kept the client alive and rendering. At 1440p the native to DLSS switch still
crashes inside the NVIDIA Vulkan driver from `slReflexSleep` (`hs_err_pid41048.log`, `pid2200.log`).
The crash is after the DLSS feature is rebuilt, not in a Reflexium pass. With Reflex Off the same
toggle does not crash, so the trigger is the driver's Reflex sleep against the rebuilt DLSS
feature. The bridge now disables DLSS-G before a surface change, sets Reflex Off for 30 transition
frames and re-applies the user mode after the transition, but the 1440p case remains open.

Other open items:

- Raw NGX SR/FG and the raw `VK_NV_low_latency2` path were not deleted. The Streamline path is the
  default, but the fallback still compiles and can be selected with `-Dreflexium.streamline=false`.
- DLSS-G status 2 with Streamline SR is still logged by the SDK even though generation is correct.
- Fullscreen, alt-tab, minimize, device loss and the PCL stats message are not covered this round.
- The BSL 1440p DLSS matrix and the shaderless final matrix were not re-run on the final build.
