## Fixes in this round

### 1. Streamline shutdown crash

Round 11 failed when closing: `WrongMethodTypeException: handle's method type (long)int but
found (MemorySegment)int` in `StreamlineBridge.invokeInt` from `ownsSurface` during surface
destroy. The native export `rx_sl_owns_surface` takes a `MemorySegment`; the call reached a
helper that declared a `long` argument.

- `StreamlineBridge` now dispatches every handle through typed `invokeExact` helpers and
  exposes its constructor and type check to the test.
- `StreamlineBridgeCheck` checks 42 export signatures, every native call site, and the
  runtime `handle.type()` of the loaded DLL. The build prints `Streamline bridge checks
  passed: 42 handles match their native signatures and every call site`.
- The dev debug HTTP server stops on client stop (`DebugServer.stop` from
  `MinecraftMixin`), so its non-daemon dispatcher does not keep the JVM alive.
- Final profile close with the debug server enabled: `CloseMainWindow` on PID 38940 exited
  in 2 s. The profile `crash-reports` latest entry before and after is the Round 11 report
  `crash-2026-10-24_23.46.23-client.txt`; no new report was written. The shutdown log ends
  with `Reflexium debug server stopped`, `Stopping!`, and no `WrongMethodTypeException`.
- Release-path profile close without the debug server: the `-Dreflexium.debugPort` line was
  removed from the launch args, so the dev-only stop path was not active. PID 39208
  auto-joined the acceptance world, rendered DLSS Quality `1707x960 -> 2560x1440`, and
  `CloseMainWindow` exited in 2 s. The crash-reports latest entry was still the Round 11
  report; no new report and no `WrongMethodTypeException`. This isolates the product fix
  from the dev tooling. The launch args file was restored afterwards.

Dev-only limit: the harness and debug HTTP servers have non-daemon dispatchers. The debug
server stop hook stops its own dispatcher; when the debug server is enabled, the dev-only
stop path also schedules a JVM exit after 1.5 s so the harness dispatcher cannot hold the
process. Release and profile launches do not start the debug server; the release-path
profile close (PID 39208) is clean without that path.

### 2. Pan smear (objective 5)

Round 11 reproduced horizontal leaf and trunk streaks while turning. Round 12 also tested
runtime jitter-sign overrides, but the sign A/B was pose-dependent and did not identify a
stable fix. The defect was in the camera constant. Representative frames from the range at
DLSS Quality and FSR Quality, 1280x720 -> 1920x1080:

| Build | Jitter sign | Result |
| --- | --- | --- |
| Before the constants fix | +1 | Smear, `selected/dev-range-before-plus-f008.png` |
| After the constants fix | +1 | Clean, `selected/dev-range-after-plus-f008.png` |
| After the constants fix | FSR +1 | Clean, `selected/dev-range-after-fsr-f008.png` |

The default jitter sign remains +1 on both axes. No override is needed after the constants
fix.

Root cause: Streamline's `clipToPrevClip` constants were built with
`DlssMath.reprojection(previousUnjittered, currentJittered, ...)`, so the current jitter was
inside the vendor camera constant while the same jitter was also supplied as
`jitterOffset`. The vendor constants must be jitter-free. `DlssMath.cameraReprojection` now
maps `previousUnjittered` to `currentUnjittered`, and all four Streamline constant sites use
it (`UpscalingRenderer.java:636`, `:686`, `:1280`, `:1290`). `DlssMathCheck` covers the new
path with identity and rotation/translation cases. The default jitter sign stays +1; the -1
override is no longer needed.

Profile forest pan, native and DLSS at the same frame index. Both show the same leaf texture
pattern, so the profile does not add an upscaler-specific streak:

- `selected/profile-forest-native-f008.png`
- `selected/profile-forest-dlss-f008.png`

Still quality note: with the camera still, the matched right-foliage crop from
`selected/profile-forest-native-still.png` and `selected/profile-forest-dlss-still.png`
gives PSNR 26.77 dB, detail correlation 0.776, and Laplacian 25.73 native vs 15.92 DLSS
Quality. The dense foliage softening remains an image-quality gap and is not claimed as a
full objective 5 pass. The round 12 motion smear itself is fixed.

### 3. Video Settings

`SodiumConfigIntegration` enabled the NVIDIA Reflex control from the applied config, so with
Frame Generation on the control stayed interactive and could set Reflex Off. The enabled
state also did not refresh after Apply. The provider now reads the draft
`frame_generation` option and depends on it:

- FG off: Reflex enabled, `selected/ui-fg-off-reflex-enabled.png`.
- FG draft on: Reflex greyed and not clickable,
  `selected/ui-fg-draft-on-reflex-greyed.png`.
- FG draft back to off: Reflex enabled again,
  `selected/ui-fg-draft-off-reflex-enabled.png`.
- Before the fix, the row accepted clicks with FG on,
  `selected/ui-before-fix-reflex-not-greyed.png`.

DLSS mode change: Upscaling Quality was changed from Quality to Balanced in the UI, applied,
and `/status` reported `quality=balanced` (`selected/ui-quality-draft.png`). It was restored
to Quality afterwards.

Saved multiplier clamp: `run/config/reflexium.properties` was set to
`frame_generation=dlss_multi` and `frame_generation_multiplier=8` before launch. The client
came up with `fg_multiplier=6`, `fg_max_multiplier=6`, `last_error=""`, and rewrote the
config to `frame_generation_multiplier=6` (`selected/clamp-evidence.txt`).

## Verdict

Round 12 fixes the two Round 11 release blockers and the two remaining UI gaps:

- The Streamline shutdown crash is gone; the final profile close is clean.
- The pan smear is fixed at the root by removing jitter from the Streamline camera
  constants. The default +1 jitter sign is restored and FSR is clean.
- Reflex is greyed and non-interactive when Frame Generation requires it, and restores the
  user choice when Frame Generation is off.
- A saved multiplier of 8 is clamped to the runtime maximum 6 with no error.

Final acceptance in the real Modrinth profile passes for the round 12 scope. Objective 5's
motion smear is fixed. Dense-foliage static sharpness remains below native (PSNR 26.77 dB,
detail correlation 0.776, Laplacian 15.92 vs 25.73), so objective 5 is improved but not
claimed as fully met.
