## 1. Runtime upscaler crash at 1440p

Root cause: `VulkanGpuSurfaceMixin.reflexium$swapchainDestroyed` cleared
`reflexium$streamlineSwapchain` at the start of `destroySwapchain`. The destroy wrapper later read
that flag and therefore called the raw driver `vkDestroySwapchainKHR` with a Streamline proxy handle
instead of the interposer destroy. DLSS-G kept its internal swapchain. The next resize created a
second swapchain, which DLSS-G rejected with `DLSS-G supports just one viewport so only one
swap-chain can be used`. `presentCommon()` then stopped running and the next `slReflexSleep`
dereferenced the stale presented state inside `nvoglv64.dll`, matching the round 8 `hs_err` stacks.

Fixes:

- The flag is now cleared at the tail of `destroySwapchain`, after the wrapped interposer destroy
  has run. The proxy swapchain is released through Streamline.
- `ReflexController` tracks whether the current swapchain has presented. It does not call
  `slReflexSleep` or emit PCL markers on a swapchain that has never presented. Sleeping on a
  freshly created swapchain after a resize was the second stale-state path.
- The extra device-idle inside the destroy hook was removed; the game already waits on its graphics
  queue, and waiting again inside the destroy transition caused a device loss during world join.

Verification: 55 runtime switches across Off/DLAA/Quality/Balanced/Performance/FSR at 1080p, 1440p
and 4K, Reflex On and On + Boost, with frame generation off, 2x and 3x, plus resizes, an alt-tab and
a world rejoin. Zero crashes. Evidence: `round9-2026-10-24/switch-matrix.csv` (55 rows, no `crash`
true), `run/logs/latest.log`.

## 2. DLSS-G status 2 with DLSS SR on

In `native/streamline/include/sl_dlss_g.h`:

```
eFailResolutionTooLow = 1 << 0,
eFailReflexNotDetectedAtRuntime = 1 << 1,
eFailHDRFormatNotSupported = 1 << 2,
eFailCommonConstantsInvalid = 1 << 3,
eFailGetCurrentBackBufferIndexNotCalled = 1 << 4,
```

Status 2 is exactly `eFailReflexNotDetectedAtRuntime`. The SDK message is
`sl.reflex must be enabled and active %d != %d`. The production `sl.dlss_g.dll` disassembly shows
the same code comparing `sl.param.latency.frame` (set by sl.reflex from the present markers) with
`sl.param.reserved.frame` (set by DLSS-G for the host frame). The values were always one host frame
apart with SR evaluating, for example `24276 != 24277`.

Root cause: the old code read `slDLSSGGetState` immediately before `vkQueuePresentKHR`. That state
still describes the previous present cycle, where the asynchronous DLSS-G pacer has not yet consumed
the current frame's Reflex present marker. Reading it after the present returns the completed cycle.
`beforeStreamlinePresent` was removed and the once-per-frame read moved into
`onStreamlinePresentResult`, after Streamline has presented the real frame plus generated frames.

Result: status 0 at 2x, 3x and 4x on BSL 1080p/1440p and shaderless 1080p/4K while generated frames
keep rising. Evidence: `fg-bsl-1080.csv`, `fg-bsl-1440.csv`, `fg-none-1080.csv`, `fg-none-4k.csv`.
The SDK log no longer contains `eDLSSGStatusFailReflexNotDetectedAtRuntime` in these runs.

Remaining gap: the product gate still treats bit 1 as non-fatal while Reflex is sleeping, because a
strict gate torn down frame generation during transitions and caused a device loss during the stress
run. Steady-state status is 0; the transition allowance is still a guard, not a clean removal. This
is reported as a partial pass for objective 6.

## 4. DLSS mip bias and terrain cost

The pinned DLSS programming guide, section 3.5, recommends
`NativeBias + log2(renderWidth / displayWidth) - 1 + epsilon`. `DlssMath.mipBias` already matches
this exactly (`log2(render/display) - 1`), and the status reports `mip_bias_vendor_baseline = -1.0`.
The rule is kept.

A/B at BSL 1440p Quality (1707x960), range pose, five second GPU timestamp windows:

| Bias | mip | FPS | Terrain GPU | World GPU | Evaluate GPU | Laplacian | Tenengrad |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| guide -1 | -1.585 | 261.9 | 1,093.8 us | 3,552.1 us | 471.7 us | 820.3 | 11,509.8 |
| guide -1 (repeat) | -1.585 | 262.7 | 1,067.6 us | 3,453.7 us | 466.7 us | 820.3 | 11,509.8 |
| log2 only | -0.585 | 261.7 | 1,081.3 us | 3,476.8 us | 442.5 us | 733.6 | 10,926.7 |
| native 2560x1440 | 0 | - | - | - | - | 650.1 | 8,809.1 |

The round 9 premise that the extra -1 costs terrain bandwidth is not supported on this pose: the
terrain GPU time is unchanged within noise (1,068 to 1,094 us against 1,081 us) and FPS is
unchanged. The guide bias is sharper than log2 on this crop. Evidence: `mip-bias.csv`,
`round9-2026-10-24/mip/`.

## 6. Reflex in CPU-bound play

Scene: shaderless 1080p, render distance 31, about 1,000 armor stands (10 doublings), 197 FPS,
GPU idle. Two ten second samples per mode:

| Reflex | FPS sample 1 | FPS sample 2 | `slReflexSleep` |
| --- | ---: | ---: | ---: |
| Off | 194.5 | 199.3 | 9.74 us |
| On | 195.7 | 202.0 | 10.3 us |
| On + Boost | 199.8 | 196.1 | 10.2 us |

This is the Valorant-style CPU-bound result: the sleep is about 10 us, not 878 us, and the FPS cost
is inside the noise. The 878 us sleep from round 8 is the GPU-bound queue-drain path at BSL 300 FPS,
not a wrong token or frame limit. The 617.42 driver still oversleeps on the GPU-bound path; that
part of objective 4 is not met. The Streamline latency report was incomplete under the armor-stand
load, so the CPU-bound latency column is absent rather than invented. Evidence:
`cpu-bound-reflex.csv`.

## 7. Transition and state-read hardening

- The interposer swapchain is destroyed through the interposer, after the flag is still set.
- Reflex sleep and PCL markers are suppressed until the current swapchain has presented.
- `slDLSSGGetState` is read once after the present, not inside the present call.
- A strict multi-frame status gate was tried and reverted: it tore down frame generation during
  transitions and produced `VK_ERROR_DEVICE_LOST`. The bit-1 transition allowance is the remaining
  guard described in section 2.
