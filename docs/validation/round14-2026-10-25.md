## Changes in this round

1. **Hardware gating.** `DlssFeatureGate` turns the results of
   `slIsFeatureSupported(kFeatureDLSS_G, adapter)` and `slDLSSGGetState().numFramesToGenerateMax`
   into one decision with a reason and a translation key. Pre-RTX 40 (feature unsupported) hides
   frame generation and MFG; RTX 40 (`numFramesToGenerateMax == 1`) allows 2x and hides MFG; RTX 50
   allows MFG. The reason is in the Frame Generation and MFG tooltips (both Sodium Video Settings
   and the Reflexium screen) and in the status line. A plugin **load** failure is reported as a load
   failure, not as an RTX 40 hardware limit.
2. **Graceful failure.** New `FailureNotice` writes one log line and queues one in-game chat line per
   distinct message. It is wired into DLSS option creation, DLSS-G load/options, frame tokens, DLSS
   evaluation and the upscaler failure path. It no longer retries after a device loss.
3. **Window state.** `FrameGenerationRenderer.onWindowState` turns DLSS-G off before a minimized
   window can stop surface recreation, resets history on restore, and records a `WINDOW_PAUSED`
   shortfall. The status line shows `(paused: window minimized)`.
4. **Device-loss detection.** `VK_ERROR_DEVICE_LOST` returned by Streamline present, acquire,
   swapchain creation or DLSS evaluation disables Streamline features without calling the SDK again,
   stops SR/FG, and shows `DLSS stopped: VK_ERROR_DEVICE_LOST. Rendering natively.`
5. **Dev-only diagnostics.** `/set dlssg_fail`, `/set device_loss`, `/set jitter_phases` and
   `/set exclusive_fullscreen` were added for the failure and input A/B tests. New status fields:
   `fg_gate_*`, `window_minimized`, `failure_notice`.

Build: `gradlew.bat build --no-daemon --console=plain` -> BUILD SUCCESSFUL. The new
`DlssFeatureGateCheck` runs in `check`.
`DLSS feature gate checks passed: pre-RTX 40, RTX 40, RTX 50, non-NVIDIA and missing runtime.`

The minimize path is the defect this round fixed: `Window.onIconified` calls
`invalidateSurfaceConfiguration`, but `Minecraft` skips `configure` while iconified, so nothing tore
down DLSS-G. The plugin stayed enabled across the pause. The explicit off-before-minimize removes
that stale active state and the restore starts a new history. Resize storms already disable FG in
`configure` HEAD, and the storm reproduced no surface-loss error or crash.

Evidence: `selected/window-evidence.txt`, `selected/storm-640.png`.

## 3. Hardware gating

`DlssFeatureGateCheck` uses mocked adapter results, so the pre-RTX 40 and pre-RTX 50 branches were
executed without that hardware. Cases: DLSS-G unsupported, RTX 40 (`maxGenerated=1`), RTX 50
(`maxGenerated=5`), non-NVIDIA, and an NVIDIA adapter with Streamline missing. Each asserts both the
decision and the reason key/text. The live RTX 5070 reports `fg_gate_fg_allowed=true`,
`fg_gate_mfg_allowed=true`, empty reason, and the forced load failure no longer shows the RTX 40
reason. Full detail: `selected/gate-check.txt`.

Limitation: no physical pre-RTX 40 or RTX 40 machine was available. The branch is proven by the
unit test and by the feature-loaded/feature-supported inputs it consumes, not by a second GPU.

## 4. Objective 5 static foliage

Same pose, same native reference, 1920x1080, vanilla renderer, vanilla leaves.
Native repeats are identical on crop A (PSNR 99 dB, correlation 1.000) and 57.08 dB on crop B, so
the scene is static and the comparison is repeatable.

| Arm | Crop A PSNR / corr / Laplacian | Crop B PSNR / corr / Laplacian |
| --- | --- | --- |
| Native repeat | 99.00 dB / 1.000 / 52.05 | 57.08 dB / 0.9999 / 45.24 |
| DLAA (1:1) | 25.93 dB / 0.844 / 33.68 | 26.50 dB / 0.850 / 29.70 |
| Quality, Auto | 25.82 dB / 0.834 / 34.41 | 26.37 dB / 0.841 / 30.45 |
| Quality, Transformer K | 25.82 dB / 0.834 / 34.39 | 24.38 dB / 0.829 / 29.93 |
| Quality, 18 phases | 25.53 dB / 0.815 / 35.34 | 23.70 dB / 0.806 / 30.72 |
| Quality, 64 phases | 25.90 dB / 0.839 / 34.06 | 23.91 dB / 0.829 / 29.57 |
| Quality, bias -2.085 | 25.79 dB / 0.833 / 34.83 | 26.36 dB / 0.841 / 30.59 |

Input audit on the captured Quality frame:

- Jitter: 32 Halton(2,3) phases, index 14, `x=-0.0625 px`, `y=+0.3148 px`, sign `+1,+1`, sent value
  equals the rendered offset.
- Motion vectors at rest: 81,600 crop pixels, 0 moving, mean/max 0.0000 px; independent capture check
  p99 0.0001 px, 100% within a quarter pixel.
- Mip bias: requested -1.5849625; `u_BlockTex` had 3/3 corrected binds with `applied_bias`
  -1.5849625. No `Sampler0`, pack or DH binds in this vanilla pose.
- Exposure: `pre_exposure=1.0`, `vendor_auto_exposure=false`; the scene is finished SDR. The pack HDR
  path was not active, so no exposure texture is expected.
- Preset: requested 0 (Auto).

Conclusions:

- DLAA at 1:1 is **not sharper than Quality** on the same leaves. The residual is not the 0.667
  upscale ratio alone; it is the temporal reconstruction of alpha-tested cutout leaves.
- Auto and Transformer K are identical on crop A. K is 2.0 dB worse on crop B, so the shipped Auto
  default is retained.
- 18 phases (the guide table minimum for Quality) is worse. 64 phases is marginally better on A and
  worse on B. The shipped 32-phase policy is the best compromise.
- More negative texture bias adds Laplacian energy but not matched detail. The guide bias
  (-1.585) is retained.
- DLAA keeps bias 0 at 1:1. That is a deliberate deviation from the guide formula's unconditional
  -1 term; the captures did not show it recovering matched detail.

No input became a code fix this round: every numeric prerequisite checked conforms. Objective 5
static foliage remains **not fully met** (PSNR about 26 dB and detail correlation about 0.84 against
native at DLSS Quality/DLAA). The honest residual is the cutout-leaf reconstruction, not jitter,
exposure, preset, mip bias or motion vectors. Evidence: `selected/input-audit.txt`,
`selected/foliage-metrics.csv`, `selected/foliage-compare.png`.
