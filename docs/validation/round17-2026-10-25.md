# Round 17: launch stability, object capture and DLSS CPU attribution

Date: 2026-10-25. Branch `round6-validation`, baseline `0eb40fc`, PR 1.
Implementation commits: `f14e0df` and `be61e2e`.
Saved-DLSS startup is fixed and passed five of five final-artifact launches. Sodium's packed writer
now stays available while capturing object motion. The CPU investigation corrected an attribution
error; it did not remove 0.56 ms of compute. The twelve-row matrix below includes rejected samples.

## Fixed

- The detached Modrinth launcher omitted `-XX:StackShadowPages=32`. Mojang's 26.3 manifest includes it,
  but Modrinth's cached Fabric version JSON does not. Resource worker stack probes crossed the stack guard.
  Reproduction without Reflexium reached the same `jvm.dll+0xa88377` address as round 16.
  `-Xss4M` was already present and did not fix it. The launcher now supplies the required reserve.
- Ryan's `javaw.exe` correction is retained. Launches have no Java console on the primary monitor.
  Optional harness injection puts the jar and game directory in the actual Windows command line,
  allowing authenticated shutdown ownership checks even when Java uses argument files.
- `ObjectMotion.SodiumCapture` implements Sodium 0.9.2's `VertexBufferWriter`. It records the packed
  position and UV stream before forwarding the original batch, including format offsets and culling.
  It preserves the scalar path when the downstream consumer cannot use intrinsics. It does not skip
  static objects, so an object that starts moving still has its complete previous frame.
- Construction is isolated behind a factory returning the base capture type. The Sodium-free test
  caught JVM verification resolving the optimized subclass before the presence branch could run.
  The same scalar/history/hand checks now pass with Sodium absent from the runtime classpath.

Five of five fresh launches with saved `upscaler=dlss`, Quality and FG off reached a loaded world.
Each reported Vulkan, `1280x720 -> 1920x1080`, no upscaler error and a rising evaluated-frame counter.
All windows stayed at `(2560,0)`, 1920x1080, on the secondary XF250Q. The foreground HWND was unchanged.
See `round17-2026-10-25/final-launches.json` and the per-launch status evidence. The early candidate
also passed five launches; the final five were repeated after `be61e2e`.

The final built jar, copied test jar and documented `installReflexium` target all have SHA-256
`72053499331FD4C9A32B0E54B0B5129A3C09667DB78C4629F6F2988214CBC587`.
`build --no-daemon --console=plain` and the existing assertion checks passed. The added check compares
packed and scalar capture across entity, block, position-only and reordered vertex layouts, including
a downstream writer that mutates its input. The profiler check covers repeated-call aggregation.

The moving-mob check tracked four entities, captured up to 1224 vertices and drew up to 816 moving
vertices. No Sodium optimized-writer warning appeared. The motion visualization shows colored vectors
on a moving pig against zero-motion ground and fences. The crop also includes the sheep used for
controlled small translations. This proves the live producer remains active; it is not a new claim of
full image-quality acceptance. Static foliage softness from round 15 remains outside this fix.
The final artifact also captured 1464 vertices and drew 816 across four entities in final launch 5.

## CPU investigation

Round 16's table reports mean time per call. `submit_fence_wait` runs about six times per frame.
Multiplying each mean by its sample count and dividing by world frames gives 1120.9 us native and
1723.0 us Quality, an increase of 602.2 us, rather than the table's roughly 96 us mean-call increase.
That accounts for most of the supposed 560 us of unscoped CPU work.

The final build adds `world_fence_wait` and scopes target setup/restoration, global uniform updates
and feature preparation. At the frozen route pose `(180.5,121.62,60.5)`, yaw 60, pitch 20, Mellow, full
profile and DH, the 12-second diagnostics gave:

| Span | Native CPU us/frame | DLSS Q CPU us/frame | Difference |
| --- | ---: | ---: | ---: |
| World including upscaling | 1837.0 | 2417.0 | +580.0 |
| Completion waits inside world | 834.8 | 1290.5 | +455.7 |
| World span after subtracting waits | 1002.2 | 1126.5 | +124.3 |
| DLSS evaluate, including constants/tags | 0 | 71.9 | +71.9 |
| Target setup and restoration, including uniforms | 0 | 3.9 | +3.9 |

GPU world time rose from 956.2 to 1383.9 us, and evaluation itself cost 588.5 us GPU. The extra world
time mostly reflects completion waiting for that GPU work. Streamline constants and tags already
lie inside evaluate. Display-depth resolution is outside the world span and had zero calls. Uniform
updates cost 1.7 us total, already included in the setup/restoration row. Do not add overlapping spans.

The alleged 0.56 ms CPU-compute block was an attribution error, so this round does not claim to have
optimized it away. Extra CPU time excluding the waits is about 0.12 ms at this pose. Required waits
remain, and the fixed GPU evaluation cost still limits FPS. The profiler now reports per-world-frame
CPU totals as well as per-call means so repeat calls cannot be mistaken for one frame's cost.
The frozen diagnostic is a different workload from the moving Benchmark Mod route; none of its FPS
readings are used in the headline matrix.

## Measurement setup

All experiments use `Fabric 26.3 RxRound17`, a new copy of Ryan's Fabric 26.3 profile. Benchmark data is
in `Documents/Benchmark Mod RxRound17`, copied from the round 16 scene. Ryan's real Fabric profile and
Testing Instance were not launched. Only the authorized `installReflexium` target was written.

The secondary panel is physically 1920x1080. Round 16's 2560x1440 window spilled outside it, so this
round uses 1920x1080 and does not claim a direct percentage improvement over round 16. Render distance
is 8, uncapped maxFps 260, VSync off, Reflex off, FG off, Transformer presets, master sound zero.
All launches use `tools/launch-modrinth-profile.ps1` and detached `Win32_Process.Create`. Initial crash
reproductions used its old `java.exe`; after Ryan reported the primary-monitor console, those clients
were closed and all launch checks and measurements used `javaw.exe`.
PID 25084 was not touched. No test took OS input focus. The original OLED overlay process was no longer
present at shutdown, so a detached primary-only copy of `oled-overlay.ps1` was started and left open.
Its verified bounds are `(0,0)`, 2560x1440. All owned clients and their listening ports were gone before
browser-based report rendering. The DH jar was restored to the copied profile after its DH-off batch.

The route and its keyframes are unchanged. An owned preparation save generated the surrounding
44 by 46 chunk corridor before measurement and copied that terrain back into the owned scene copy.
DH distant generation is explicitly disabled with `generatorPlan=DISABLED`; its cached LOD rendering
remains enabled for the DH rows. The preparation checks confirm the tile corners loaded before saving.
The saved DH configuration retains all values and omits its generated comments and blank lines.

Each mode uses three Benchmark Mod passes in one loaded world. Pass 0 conditions the scene and is
excluded. Passes 1 and 2 form the reported pair. Warmup is 8 seconds; the route's measured portion is
45 seconds after its lead-in. All reported passes have `settleRelease=ready` and no settle timeout.
A crop is read back inside each measurement
window near route second 24, with its status, pose, pack, internal size and evaluated counter recorded.
The two 320x180 crops share one 640x180 PNG. No full-size screenshots are saved. Mode changes wait at
least 12 seconds, then require a stable title-screen CPU/GPU window before starting. The initial
matrix attempt failed that idle proof and is discarded. Profiling is off for the headline captures.
The single screenshot readback in each measured pass remains in the raw timing; its cost is not
subtracted. Status polling is limited to the paired capture boundaries.

Content floors were set to mean luma above 8, variance above 80 and more than 150 horizontal/vertical
edges with luma difference above 12. Native correspondence requires direct normalized correlation
above 0.65 and correlation above 0.75 within a 12-pixel translation search. Pose differences against
the native capture must be within 0.25 blocks and 0.25 degrees. The reference crop is near
`(180.104,121.676,58.998)`, yaw 59.187, on every repeated route pass.

The DH-on batch used `f14e0df`, jar SHA-256 `294383987E75AF9A94038521C508CAF807B49155148BE0340A218CF69D9D944D`.
The final build adds only the optional-class construction isolation to the active capture path. The
DH-off batch and final launch checks use the final SHA-256 above. Each native/DLSS comparison stays
within its own batch and artifact. These measurements do not quantify an old-versus-new FPS benefit.

The Mellow DH-off center crops are almost uniform grey at the documented mid-route pose, including
native: luma 175.9, variance 0.95 and zero qualifying edges. Quality and Performance have variance
about 0.5 and zero edges, and also fail native correlation. These are invalid FPS/image results,
despite matching mode status and repeatable averages. The native failure prevents attribution to
DLSS. The pack's border-fog code removes scene color near its far limit; fog is a possible explanation,
not a verified diagnosis of the entire frame. The existing crop and thresholds were retained, and
no lower floor or replacement image was selected to accept these rows. This round therefore has no
accepted Mellow DH-off comparison.

All nine remaining rows pass the stated content, pose, mode, pack, idle and backend checks. Their
average pairs agree within 3 percent. BSL Performance with DH has a clear average gain; the +1.8%
Quality/DH and +0.4% Performance/no-DH differences are smaller than the repeat tolerance. Mellow/DH
loses 17 to 19 percent and BSL Quality/no-DH loses 6 percent. The 2026-10-25 decision log accepts
1080p fixed-cost losses; these measurements still show them.

Most tail pairs remain unstable. Even where a DLSS low passes, its matching native low does not, so
there is no accepted relative 1% low improvement in this matrix. Eliminating the Sodium warning is
verified by the capture checks and live mobs, but the round 16 claim of a 172 to 115 FPS causal tail
loss is not quantified by a stable before/after pair here. Different resolution, preparation and
artifacts also prevent claiming an FPS gain over round 16.

## Remaining limits

- Task 3's requested 0.56 ms compute reduction was not achieved. Most of that supposed block was
  repeat-call fence-wait accounting. About 124 us/frame of extra non-wait CPU remains at the frozen
  diagnostic pose, including 72 us evaluation. Evaluation also costs about 589 us GPU there.
- Mellow without DH has no valid content comparison on this route crop. Its cause remains open.
  The three rejected raw rows must not support a performance or image-quality claim.
- Most 1% lows fail repeatability. No reliable old/new tail benefit is established.
- Round 15's foliage/detail limitation remains. The mob diagnostic establishes producer activity and
  displacement handling, not full objective 5 acceptance.
- This is a 1080p Q/P, FG-off round on copied profiles. Balanced, DLAA, shaderless, 1440p/4K, FG,
  window-mode/device-loss coverage and the complete release objectives are not re-certified.
  The real Testing Instance was not launched because the current task forbids experiments there;
  only its authorized installed jar hash was verified.
- Benchmark Mod exposes no Vulkan chunk queue telemetry in these results. Terrain preparation,
  disabled DH generation and the excluded first pass control generation load, but zero queue activity
  is not directly instrumented. The file's `renderDistanceMismatch` flag is the unchanged scene hint
  of 16 versus the explicitly measured 8. Its `renderer.shadersEnabled=false` is the known Vulkan
  detection defect; Reflexium status and the log supply the pack proof.

## Reproduce the evidence checks

From this repository, with PowerShell and Node installed:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File docs/validation/round17-2026-10-25/check-images.ps1
node docs/validation/round17-2026-10-25/summarize.mjs
```

The first command recomputes and writes `image-check.json`; the second rebuilds
`results-summary.json` from the saved statistics, raw Benchmark Mod files and per-window status proof.
Neither command launches a game or changes a profile. There are fourteen PNG evidence files, all no
wider than 640 pixels: twelve paired route crops and two moving-mob crops. The inline report preview
uses no additional game capture.
