# Reflex choices with NVIDIA frame generation

Merged `round6-validation` at `dd553198` before editing. Runtime Reflex behavior and
`ReflexController.mode()` are unchanged.

Sodium now uses hardware support for enabled state and a `frame_generation`-dependent
allowed-values provider to exclude Off while NVIDIA FG is requested and has not failed.
The default On remains allowed. The fallback dropdown uses the same two-value list and
stays active when Reflex is supported. The vanilla option uses a dynamic `AltEnum` list;
its button refreshes the effective value without persisting a forced On over stored Off.
The tooltip now says Off is unavailable while NVIDIA frame generation is on.

## Live checks

Windows 11, RTX 5070, Vulkan, Streamline Reflex. Real mod set: Sodium 0.9.2,
Reese's Sodium Options 2.2.5+mc26.3, Iris snapshot 1.12.0, Meshelium 1.6.2, Mod Menu.
Secondary monitor 1920x1080, behind, muted. Foreground and input focus remained false.
The overlay was left alone. Only isolated `run/` was modified. Owned clients exited by
authenticated quit and the GPU lock was released after each exit.

- FG off: Off is available and the Reflex row is enabled.
- FG changed on the same page before Apply: Off displays as On, without strikethrough.
  Repeated clicks cycle On, On + Boost, On, skipping Off. No crash.
- FG 3x and On + Boost applied: the Apply button becomes disabled and the row loses its
  pending-change italics. Status reports `reflex_mode=ON_BOOST`, Streamline flags
  `[true,true]`, `frame_generation=dlss_multi`, `fg_multiplier=3`, empty `last_error`.
- Cold open with stored Off and already-applied FG 3x: displays On, no strikethrough,
  no pending-change italics and Apply disabled. Stored `reflex_mode=off` is preserved.
  Selecting Boost and applying succeeds in that state too.
- Fallback screen: active Reflex button, exactly On and On + Boost in its choice list.
  Both choices were applied live and confirmed by status.

Sodium's native pending-value behavior is retained. Its `EnumOption.validateValue` replaces
a disallowed value with the default. `StatefulOption.getValidatedValue` stores that result
in `modifiedValue`, and `applyChanges` saves it. Consequently, starting with stored Off,
switching FG on and then back off before Apply leaves **On pending**, rather than restoring
Off. Undo restores Off and clears the dirty state. Apply would persist the coerced On unless
the user selects another value. This is an actual pending value change, not an orphaned dirty
flag. No preference-restoration machinery was added. Keeping the original effective-mode
binding avoids a phantom change on cold open with stored Off and FG already enabled.

The initial UI pass used JAR SHA-256 `1948BFFCBC0A2148716EB592C894BF276276151D985B065C68259271081036A2`.
The final build restores the original Sodium getter, preserving clean cold-open behavior.
Final SHA-256: `780C8C7AFDB882B7660C5BD76D9DFCF8448B287942E8CB53781090F41B015CC8`.
Final build's cold-open and Boost-apply checks are separately captured. The getter difference
does not change the earlier stored-Off/FG-off pending-choice tests.

`gradlew.bat build --no-daemon --console=plain -PreflexiumInstallDir=build/install` passed all
checks, including the allowed Reflex choices in `UpscalingContractCheck`. The final build
log is saved. The vanilla-only Video Settings path was checked against mapped bytecode and
compiled, but not live-tested without Sodium. Unsupported hardware was not available live;
its existing support gate remains in place.
