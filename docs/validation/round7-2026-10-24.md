# Round 7: DLSS-G generation, readable Reflex latency, and the final path, 2026-10-24

This round removed the DLSS-G blocker that survived rounds 5 and 6, made Reflex latency readable on the
Streamline path, re-ran the release matrix on the final path, and profiled the remaining BSL loss.
Every frame-rate row follows the [OBJECTIVES.md](../OBJECTIVES.md) validity rules.

## 1. Root causes of the DLSS-G blocker

Five independent defects kept generated presents at zero. Each was reproduced in the SDK log before the
fix and re-tested in game after it.

1. **Streamline never owned the swapchain.** `StreamlineSupport.swapchainReady()` returned false until
   `rx_sl_create_swapchain` had run, but that call was gated by the same method. The interposer
   present was therefore never used and `sl.common` reported "presentCommon() was not observed".
   The proxies are now resolved in `rx_sl_set_device`, before the first swapchain exists.
2. **The surface was unknown to Streamline.** SDL created the window surface through the loader, so the
   interposer had no surface-to-HWND mapping and `vkCreateSwapchainKHR` failed with
   `VK_ERROR_INITIALIZATION_FAILED`. `VulkanGpuSurface` now creates the surface through the interposer's
   `vkCreateWin32SurfaceKHR` proxy and destroys it through the matching proxy. The SDK log then reports
   `HWND for surface ... resolved ... via interposer surface map`.
3. **DLSS-G's extra queues were missing.** The device had one graphics/compute queue. The bridge now
   reserves one graphics and two compute queues in the game's family, sets their priorities and queue
   count, and reports the first Streamline queue index through `slSetVulkanInfo`. The log shows
   `Reserved Streamline queues 1..3 in Vulkan family 0`.
4. **The feature-loaded flag started false.** `slInit` loads `sl.dlss_g`, but the bridge initialized its
   state to false. The first world frame then requested a load and recreated the swapchain during
   startup, which failed. The initial state is now true, so a load transition only happens when the
   application changes it.
5. **Reflex present IDs were missing on the Streamline path.** `VkPresentIdKHR` was deliberately not
   chained when Streamline owned the present, so the driver published no Reflex frame reports. The
   present IDs are now chained for every real present, including the Streamline path.

`VK_SUBOPTIMAL_KHR` is still accepted as a delivered present, and DLSS-G options are applied only when
the requested mode or generated count changes.

## 2. DLSS-G generation on the final path

BSL v10.1.8, Performance, 1920x1080 range pose (200.5, 151, 0.5, yaw 0, pitch 3), focused client,
5 second windows after a 4 second settle:

| Multiplier | Real FPS | Generated per second | Output FPS | Generated per real |
| --- | ---: | ---: | ---: | ---: |
| 2x | 231.8 | 231.8 | 463.6 | 1 |
| 3x | 195.0 | 390.0 | 585.0 | 2 |
| 4x | 172.4 | 517.2 | 689.6 | 3 |
| Auto | 310.6 | 0 | 310.6 | 0 |

The Auto row selected 1x because the real rate was above the 223 FPS refresh-headroom budget, which is
the documented behavior for Auto only. Fixed multipliers did not use that budget, so objective 3 holds.
`slDLSSGGetState` reported status 0 and `numFramesActuallyPresented` rose with `numFramesToGenerate`.
The output rates are submitted presents, not a scanout measurement.

A second, earlier run on the same path measured 2x at 213.6 real / 427.2 output, 3x at 182.4 / 547.2
and 4x at 157.0 / 628.0. The absolute level depends on the scene and the pack settling; the ratios did
not.

## 3. What the DLSS-G fixes changed

- `native/reflexium_sl.cpp`: proxy resolution at device registration, interposer surface create/destroy,
  queue reservation helpers, feature-loaded state, DLSS-G options layout, PCL state readout.
- `VulkanGpuSurfaceMixin`: surface created through the interposer, per-swapchain proxy tracking,
  DLSS-G state read immediately before the present, tag clearing on menu, feature unload between
  swapchains.
- `StreamlineSupport`: feature load/unload transition, present-thread state cache, extra options
  dimensions, PCL stats message.
- `VulkanBackendMixin`: reserves Streamline queues alongside the existing FSR reserve.
- `VulkanLifecycle`: present IDs are chained on the Streamline path.
- `ReflexController`: present IDs enabled for Streamline, PCL marker 6 no longer emitted because
  `eInputSample` is deprecated and the Vulkan LL2 backend rejects it.
- `FrameGenerationRenderer`: state read moved to the present thread, status-2 (Reflex not detected)
  treated as transient instead of fatal, minimum-size gate, tag clearing, UI recomposition behind
  `-Dreflexium.fg.ui=false` for diagnosis.

## 4. Reflex latency and cost

The Frame Report is now populated on the Streamline path. `reflex_timings` and the F3 line return
values, and `slReflexGetState` reports a real `frameReport` for the latest presented frame.

BSL 1080p range, Performance, 1x (no frame generation), two 5 second samples per mode:

| Reflex | FPS sample 1 | FPS sample 2 | Render latency |
| --- | ---: | ---: | ---: |
| Off | 337.8 | 336.0 | 6.0 ms |
| On | 314.8 | 312.8 | 5.3 to 6.0 ms |
| On + Boost | 312.6 | 315.6 | 4.6 to 4.8 ms |

Shaderless 1080p range, upscaling off, two 5 second samples:

| Reflex | FPS sample 1 | FPS sample 2 | Render latency |
| --- | ---: | ---: | ---: |
| Off | 1,535.2 | 1,525.4 | 1.3 ms |
| On | 1,363.4 | 1,363.6 | 0.9 ms |
| On + Boost | 1,364.0 | - | 1.2 ms |

The reported value is the driver's GPU render end minus simulation start. It excludes display latency
and scanout. Reflex On and Boost reduce it, but the FPS cost is 6.9% at 315 FPS and 10.9% at 1,500 FPS
on this driver. A profile of the Streamline sleep call shows 796 us inside `slReflexSleep` with On
against 11 us with Off, while the submit wait drops by about 600 us. The remaining cost is the 617.42
driver oversleep already recorded in the brain, not a Reflexium pass.

The PCL input-sample marker is not emitted: `eInputSample` (6) is commented out in the 2.14.16 header and
the Vulkan LL2 backend rejects it. The other PCL markers (simulation, submit, present, flash) are mapped.

## 6. Pans and moving mobs on the final path

BSL 1080p range, Performance, DLSS-G 2x, `reflexium:spawn_mobs`:

- Real stills at the same pose: native mean luma 151.5, variance 2,704; Performance mean 151.1,

- Eight real frames of a 90 degree pan (350 ms spacing) show smooth motion with no doubling or ghost

## 9. Remaining gaps

- Generated-frame image capture on the Streamline path. The SDK does not expose generated images.
- Streamline SR with DLSS-G on. The shared-constants path returns `eErrorInvalidParameter` when DLSS
  evaluates against the flipped inputs, and the configuration that does evaluate makes DLSS-G report
  status 2 and stop. Raw NGX SR remains the default with FG on.
- Reflex sleep cost at high FPS. The 617.42 driver spends about 0.8 ms inside the sleep call.
- BSL shadow-path cost at the DLSS viewport. It is in Iris or BSL, not in a Reflexium pass.
- The 1440p forest Quality loss and the 1080p range Quality loss are profile-complete but not fixable
  from this repository without a pack or Iris change.
- Fullscreen, alt-tab, minimize, device loss and the PCL stats message remain unverified.
