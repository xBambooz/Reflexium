# Frame generation and Reflex validation, 2026-10-14

Status: implementation and test checks completed for the 12 specification requirements. Correct engine integration, lifecycle resilience, GPU synchronization invariants, and accurate telemetry reporting have been established. Physical scanout cadence and external driver-level pacing anomalies remain bounded by hardware and driver limitations.

Windows 11, Java 25.0.4, Minecraft 26.3, GraalVM JDK 25.0.4+7.1, Vulkan, RTX 5070, driver 617.42.

- `.\gradlew.bat build --rerun-tasks --console=plain`: passed, including `dlssMathCheck`, `frameDeliveryCheck`, `frameProfilerCheck`, `objectMotionCheck`, `reflexTimingCheck`, `upscalingContractCheck`, `installReflexium`, and `jar`.
- `native/build.cmd`: compiled clean with MSVC v143 (Visual Studio 2022). Both `reflexium_ngx.dll` and `reflexium_fsr.dll` were compiled and verified in `src/client/resources/natives/windows-x86_64/`.
- `FrameDeliveryCheck`: standalone JUnit/assertion check covering surface image count clamping (min/max bounds and unbounded max=0), extension revision gating (specVersion 0..3), matching 1-second presentation stats submission windows, suppression reset on invalidation, present metering feedback (success, error, rejected), partial batch swapchain out-of-date failures, suboptimal swapchain fallback, and warmup resets.
- `ReflexTimingCheck`: standalone assertion check covering `PacingState` transitions, initial configuration, cap ownership requiring completed sleep, configuration failure retaining previous valid records without spamming, wait timeout/failure fallback to vanilla limiter, Off-mode sleep reporting without claiming cap ownership, and lifecycle recovery.

## Requirement outcomes

| Spec item | Implemented behavior and evidence | Remaining acceptance |
| --- | --- | --- |
| 1. Reflex mode failure handling | `PacingState` tracks attempted vs applied mode and interval. State is committed only upon `VK_SUCCESS` from `vkSetLatencySleepModeNV`. On failure, the previous valid state is preserved, `ownsFrameLimit()` returns false, and the FPS cap is returned to vanilla. Deterministic checks pass in `ReflexTimingCheck`. | Driver crash or hang inside the driver runtime cannot be intercepted beyond Vulkan return codes. |
| 2. Sleep timeout and lifecycle | `drainSleep()` checks and waits on pending timeline semaphore signals before launching a new sleep. `VK_TIMEOUT` and failures mark `pacing.sleepResult(result)`, making failure observable and returning frame capping to vanilla without stalling. Failures clear cleanly across swapchain and device boundaries. | Driver-level oversleep observed on driver 617.42 remains an external driver characteristic. |
| 3. Surface image count limits | `VulkanLifecycle.chainSwapchainLatency` queries `vkGetPhysicalDeviceSurfaceCapabilitiesKHR` and uses `validImageCount(original, min, max)`, honoring physical surface limits (including `maxImageCount=0` as unbounded). Tested in `FrameDeliveryCheck`. | Dynamic surface format changes during runtime window migration across heterogeneous monitors. |
| 4. Attribution and FG markers | Explicit attribution is applied strictly to the graphics queue when revision >= 3. `clearSubmissionAttribution()` emits an explicit present ID 0 submit to clear queue tracking before/after FG batches. In `VulkanGpuSurfaceMixin`, replacement submits are enclosed in `OUT_OF_BAND_RENDERSUBMIT_START_NV` / `END_NV`, and generated presents use `OUT_OF_BAND_PRESENT_START_NV` / `END_NV`. `FrameTrace` provides bounded per-frame logging. | Verification with external vendor hardware tools (LDAT/PCL). |
| 5. Extension revision check | `DeviceExtensions` enumerates extension properties to read `specVersion` for `VK_NV_low_latency2`. `VulkanSession` exposes `explicitAttributionSupported()`, requiring revision >= 3. Tested for revisions 0 through 3 in `FrameDeliveryCheck`. | Devices advertising non-conformant specVersion integers. |
| 6. FG metering feedback | `chainMetering` initializes feedback to -1. `onPresentResult` inspects `presentConfigFeedback`. If rejected or if `vkQueuePresentKHR` returns an error, the batch is rejected, interpolation is abandoned, and the real image is delivered immediately. Checked in `FrameDeliveryCheck`. | NVIDIA present metering is a provisional Vulkan extension. |
| 7. Accurate FPS reporting | Removed the global `Minecraft.getFps()` override. `PresentationStats` records successful real and generated submission timestamps over an elapsed 1-second window. `FpsText.withRendered` appends `(rendered) fps submitted` only when generated frames are actively submitted. Resets cleanly on warmup, menu blur, and camera cuts. | Actual display panel refresh and hardware scanout cadence. |
| 8. AMD scheduler callback lifetime | `fsr_swapchain.h` introduces `ScheduledFrame` passed through `frameGenerationCallbackUserContext`. `copyGenerated` verifies `params->frameID == frame->id`. `scPending` prevents concurrent overwrites. Return codes from wait, pause, and destroy are propagated instead of swallowed. Incompatible raw Reflex structures in pNext are rejected at proxy creation. | Testing on native AMD/Intel silicon (tested via NVIDIA fallback route). |
| 9. Acquire semaphore synchronization | Removed the arbitrary 16-semaphore allocation. Implemented `reflexium$acquireCompletion` fences tracking the command submission consuming each binary acquire semaphore. Before any acquire semaphore is reused, its prior consuming submission is guaranteed complete via `awaitCompletion`. | Non-standard third-party Vulkan layers intercepting swapchain semaphores. |
| 10. Reflex caps and input timing | Frame sleep occurs exactly once per application frame in `MinecraftMixin.run` immediately prior to SDL event polling. FPS interval uses ceiling integer math (`(1_000_000L + fps - 1) / fps`). VRR headroom is explicitly labeled as a heuristic in debug text. Left-click trigger flash is dispatched via `MouseHandlerReflexMixin`. | Automatic detection of active G-Sync / VRR hardware engagement from Vulkan. |
| 11. Latency telemetry discipline | `LatencyReport` rejects non-positive, inverted, and GPU end < start timestamps. Reports older than 1 second are flagged as stale. `timingFloorId` invalidates stale data after mode transitions. `DebugServer` explicitly exports `fg_display_feedback: "unavailable"`. | In-engine telemetry measures simulation-start to GPU-completion; it does not measure mouse hardware or display scanout. |
| 12. Verification and delivery | Automated test suite (`gradlew build`) includes all contract and lifecycle checks. Native binaries rebuilt and packaged. Diagnostic endpoints report submitted rates and explicit attribution state. Stale documentation updated. | Independent display capture via external hardware capture card or ETW display trace. |

## Technical limits and conclusions

1. **Submitted rate vs physical scanout**: Reflexium measures and reports operations submitted to the Vulkan presentation queue. It does not claim physical monitor scanout or panel flip synchronization.
2. **Reflex driver pacing**: The high-FPS pacing overhead and timing inversions under driver 617.42 reproduce in isolated C++ references without Minecraft or Java. Reflexium handles driver return codes and timeouts without hanging, but cannot fix underlying driver-level queue pacing quirks.
3. **Hardware coverage**: DLSS FG and MFG were validated on an RTX 5070 running Vulkan. AMD FSR FG was validated using the SDK scheduler route on the same hardware. Verification on native AMD and Intel silicon remains open for testing by users with corresponding hardware.
