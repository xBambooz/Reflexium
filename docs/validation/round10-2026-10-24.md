# Round 10: Streamline-only cleanup, DLSS-G ordering, generated frames and acceptance, 2026-10-24

This round deletes the raw NGX and raw `VK_NV_low_latency2` paths, removes the DLSS-G bit-1
transition allowance, measures the 1080p DLSS evaluate cost, labels real and generated frames from
present timing, and re-runs the NVIDIA audit and the real Modrinth profile. Every FPS row follows the
[OBJECTIVES.md](../OBJECTIVES.md) validity rules unless marked otherwise.

- Windows 11, RTX 5070 12 GB, NVIDIA 617.42, GraalVM Java 25.0.4, Minecraft 26.3, Vulkan.
- Streamline 2.14.16, BSL v10.1.8, Iris `1.12.0-snapshot+mc26.3-local`, Sodium 0.9.2.
- Harness client 1920x1080, 2560x1440 or 3840x2160 on the secondary XF250Q display. The 55-switch
  matrix and the WGC captures ran with `-Activate` and input focus while that was allowed. The
  focus permission was revoked at the end of the round; no further focus capture was made.
- Range pose (200.5, 151, 0.5, yaw 0, pitch 3), render distance 31, simulation distance 12, VSync
  off, Max Framerate 260 (Unlimited). FG rows used fixed multipliers; `frame_generation` was set
  before `fg_multiplier` because selecting a DLSS FG mode resets the multiplier to Auto.
- The client was closed by `/quit` and its exact PID, never by process name. The OLED overlay was
  not touched.

## 2. DLSS-G Reflex ordering and the bit-1 allowance

The pinned DLSS-G guide, section 8.0, says:

> **It is required** for sl.reflex to be integrated in the host application. **Any existing Reflex
> SDK integration that does not use Streamline cannot be used with DLSS-G.** Pay special attention to
> the `eReflexMarkerPresentStart` and `eReflexMarkerPresentEnd` markers, which must provide the
> correct frame index so it can be matched to the one provided in Section 7.

`sl_dlss_g.h` describes bit 1 as `eFailReflexNotDetectedAtRuntime`: "Reflex is not active while
DLSS-G is running, Reflex must be turned on when DLSS-G is on". The pinned guide and header do not
document a one-frame Reflex-detection lag. A permanent allowance for bit 1 is therefore not
supportable, and the old `status == 2 && isSleeping()` gate was removed.

The ordering was fixed instead:

- `ReflexController.noteFrameGenerationRequested` records the completed-sleep count when an NVIDIA
  mode is requested. DLSS-G options are not enabled until two Reflex sleeps have completed with the
  configured Reflex mode and interval, so `sl.reflex` has marker history before the first generated
  present.
- The status gate is strict: any nonzero `DLSSGStatus` at the post-present read turns generation off
  and surfaces the code. There is no bit-1 exemption in `FrameGenerationRenderer`.
- `slDLSSGGetState` is still read once after the present, not inside the present call.

Evidence: 63 switch rows and three resize cycles had `streamline_dlssg_status = 0` and
`fg_failed = false`. The harness log contains no `eFailReflexNotDetectedAtRuntime`,
`status 2` or `turning frame generation off` line.

The real profile exposed a different rejection: a saved multiplier of 8 asked for 7 generated
frames when the runtime maximum was 5, so `slDLSSGSetOptions` failed with 38 every frame. The
device-created path now queries `slDLSSGGetState` for the real maximum, uses a conservative 2x
placeholder before the first state query, and clamps an above-maximum request instead of repeating
it. This is a runtime-capability clamp, not a status allowance.

## 3. Generated frames at full present rate

WGC was captured on the input-focused harness window at 1920x1080, BSL Performance, DLSS AUTO. The
Reflex interval was used only to lower the real rate so every present fit below the panel rate.
Frames were separated by present timing and confirmed by Laplacian sharpness on a 320x180 world
crop. Real frames are the high-sharpness phase of each period.

| Multiplier | Frames | Capture | Median interval | Period | Real frames |
| --- | ---: | ---: | ---: | ---: | --- |
| 2x | 60 | 0.50 s | 8.33 ms | 2 | even indices |
| 3x | 48 | 0.42 s | 8.33 ms | 3 | index 2, 5, 8, ... |
| 4x | 65 | 0.43 s | 6.25 ms | 4 | index 6, 10, 14, ... |

The capture rate matches `real rate x multiplier` in every row, so every present was captured. The
sharpness sequence repeats with the expected period and the real phase is the sharper one.

Inspected crops at 960x540 (`wgc-2x-big`, `wgc-3x-big`, `wgc-4x-big`): cage bars, chains, gate
frames, the first-person hand and the crosshair stay crisp on generated frames. The flyers in the
glass cage, the cow and the horse are single objects with no doubling. No generated-only warping or
HUD interpolation was visible. The vertical sky bands are present in the real frames too; they are
the pack's sky, not a frame-generation artifact.

Boundary: the round ran the focused capture before the permission was revoked. The final exact jar
was not re-captured. WGC cannot label real versus generated frames by itself; the labels here use
the measured present period plus the sharpness phase.

## 4. DLSS evaluate cost at 1080p

BSL v10.1.8, range pose, FG off, Reflex On, five second profile windows. `evaluate` is the GPU
timestamp span of the Streamline DLSS feature only, not the whole frame.

| Model | Preset | Quality | Render size | Evaluate GPU | FPS |
| --- | ---: | --- | --- | ---: | ---: |
| CNN | E (5) | Performance | 960x540 | 261.9 us | 302 |
| CNN | E (5) | Quality | 1280x720 | 264.4 us | 282 |
| CNN | E (5) | Balanced | 1114x626 | 253.0 us | 279 |
| CNN | E (5) | DLAA | 1920x1080 | 302.4 us | 263 |
| Transformer | K (11) | Performance | 960x540 | 591.2 us | 279 |
| Transformer | M (13) | Performance | 960x540 | 648.0 us | 276 |
| Transformer | K (11) | Quality | 1280x720 | 628.4 us | 268 |
| Transformer | K (11) | Balanced | 1114x626 | 620.5 us | 268 |
| Transformer | K (11) | DLAA | 1920x1080 | 655.8 us | 242 |
| AUTO | runtime default | Performance | 960x540 | 674.2 us | 277 |
| AUTO | runtime default | Quality | 1280x720 | 610.4 us | 269 |
| AUTO | runtime default | Balanced | 1114x626 | 621.9 us | 267 |
| AUTO | runtime default | DLAA | 1920x1080 | 626.0 us | 240 |
| Transformer | L (12) | Ultra Performance | 640x360 | 648.2 us | 309 |
| AUTO | runtime default | Ultra Performance | 640x360 | 600.2 us | 304 |

Official defaults in the pinned headers are K for DLAA, Quality and Balanced, M for Performance
and L for Ultra Performance. `DlssModel.TRANSFORMER` now uses M for Performance instead of K, and
the shipped model default changed from CNN to AUTO so the runtime's own recommended preset is used.
CNN remains selectable; it is about 2.3x cheaper to evaluate at 1080p Performance but is the legacy
model, not NVIDIA's current default.

Remaining gap at 1080p, stated honestly:

- At 300 FPS the whole frame is 3.33 ms. Native BSL 1080p was 309.9 FPS (3.23 ms) in round 9.
- The render-size fill saving from 1920x1080 to 960x540 is almost consumed by 0.26 ms of CNN
  evaluation plus the other passes, giving the measured -2.1% Performance result.
- The recommended AUTO/M path spends 0.65 to 0.67 ms in evaluation alone, about 20% of a 3.3 ms
  frame, and loses about 10%. The evaluate cost, not the pixel savings, is the 1080p limit.
- At 1440p and 4K the fill saving is larger than the evaluate cost and DLSS wins. The shaderless
  deficit from round 9 is unchanged.

the Streamline-only code. All items pass after these fixes:

| --- | --- | --- |
| 1. Initialization and device registration | Pass | `VulkanInstanceMixin` calls `StreamlineSupport.beforeInstance`; `StreamlineSupport.onDeviceCreated` calls `slSetVulkanInfo`, queries DLSS/DLSS-G/Reflex/PCL and now queries the DLSS-G state ceiling. |
| 2. Reflex options | Pass | `slReflexSetOptions` with mode 0/1/2 and Boost. |
| 3. Sleep placement and frequency | Pass | One `slReflexSleep` per real frame before input polling; the no-present swapchain guard remains. |
| 4. PCL marker order | Pass with documented exception | `SIMULATION_START` follows the unmapped deprecated input-sample marker; the rest of the order is enforced and ranked. |
| 5. Trigger flash | Pass | Left click emits the PCL trigger marker while simulation is open. |
| 6. Out-of-band markers for FG | Pass | Streamline owns generated presents. FSR's application-managed proxy presents retain the out-of-band markers. |
| 7. Marker regression logging | Pass | Rank tracking and bounded warning logs remain. |
| 8. Frame ID ownership | Pass | One frame id drives the Streamline token, PCL markers and `VkPresentIdKHR`. Explicit queue submission IDs are gone. |
| 9. FPS cap | Pass | `slReflexSetOptions.frameLimitUs`; no refresh cap for fixed multipliers. |
| 10. Mode changes | Pass | Mode changes reset pacing and re-apply options; the 63-switch matrix exercised them. |
| 11. UI availability and fallback | Pass | The Reflex widget uses `StreamlineSupport.reflexAvailable()`; the config and Sodium providers use `ReflexController.isSupported()`. |
| 12. Interaction with frame generation | Pass | `mode()` forces Reflex On while FG is requested; FG is rejected with VSync on and on unsupported runtimes; fixed multipliers stay uncapped. |
| 13. Telemetry and latency reporting | Pass after fix | Streamline reports are now rejected when their present id is outside the current token window or unchanged for more than one second. |

The audit also found and fixed the profile-only above-maximum multiplier loop described in
section 2. It is not caused by a status code; `slDLSSGSetOptions` returned 38 because 7 generated
frames exceeded the runtime maximum of 5.
