The four essential upscaler inputs
Passed to NVSDK_NGX_VK_DLSS_Eval_Params and ffxDispatchDescUpscale
Input 01
Low-res color
VK_FORMAT_R8G8B8A8_UNORM
Supplies shaded scene color before HUD elements are drawn so the upscaler has raw scene lighting and textures.
Input 02
Hardware depth
VK_FORMAT_D32_SFLOAT (Reverse-Z)
Supplies surface distance so the upscaler detects geometry silhouettes, occlusions, and newly revealed pixels.
Input 03
Motion vectors
VK_FORMAT_R16G16_SFLOAT (Render pixels)
Supplies 2D screen-space pixel velocity pointing from current to previous frame to align history across time.
Input 04
Camera jitter
Sub-pixel NDC / pixel offset
Informs the upscaler how the projection matrix shifted this frame, allowing it to reconstruct sub-pixel detail.
Upscaler engine selection
Auto mode (default) Recommended
Detects hardware and picks DLSS on NVIDIA RTX graphics cards. Falls back to FSR 3.1 on AMD, Intel, and non-RTX cards.
NVIDIA DLSS RTX GPUs
Tensor Core accelerated neural reconstruction via reflexium_ngx.dll and auto-downloaded nvngx_dlss.dll.
AMD FidelityFX FSR 3.1 Universal Vulkan
Vendor-agnostic temporal upscaler with RCAS sharpening via reflexium_fsr.dll and amd_fidelityfx_vk.dll.

DLSS models: CNN vs Transformer
Auto model selection
Reflexium automatically assigns the vendor-recommended neural model for the active quality preset.
CNN models (Presets A through G)
Classic convolutional autoencoders. Low VRAM consumption (~60 MB at 1080p); fast on older Turing cards, but prone to thin-line ghosting.
Transformer models (Presets J through M)
DLSS 3.10+ Vision Transformers using self-attention. Vastly improved stability and ghosting reduction, at higher VRAM and compute cost.
Resolution swap rule: Main target always holds display textures outside the world pass, ensuring screenshots, window resizing, and the final swapchain blit work without modifications.
