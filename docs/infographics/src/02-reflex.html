How Reflex lowers latency

Synchronizing the CPU game loop with the GPU, preventing queue backlog, and enforcing refresh-rate limits

VK_NV_low_latency2
Pacing mechanics
Why Reflex lowers latency
Standard un-paced pipeline (Off)
The CPU runs ahead of the GPU as fast as possible, queueing multiple frames into the driver render buffer. User clicks wait in this queue before reaching the screen, creating noticeable input lag.
Reflex just-in-time pacing (On)
The driver sleeps the CPU via vkLatencySleepNV so the frame starts at the latest possible moment before the GPU is ready. Input is polled immediately after waking, removing queue backlog.
Timeline semaphore sync
Reflex uses an asynchronous timeline semaphore wait (vkWaitSemaphores) at the start of each frame so execution wakes precisely when the GPU needs work.
User settings
Operating modes
Reflex Off OFF
Disables latency pacing. The CPU runs unconstrained and can queue frames. Latency markers remain active so timing stats still report to F3 for comparison.
Reflex On ON
Enables dynamic frame pacing. The driver sleeps the CPU before input polling to align CPU frame generation directly with GPU execution.
Reflex On + Boost ON + BOOST
Enables pacing and commands the GPU power manager to keep core clocks pinned at maximum frequency even during CPU-heavy scenes, preventing downclock lag spikes.
Frame pacing
Frame cap and VRR auto-cap
Reflex replaces Minecraft's post-present sleep with driver-level pacing using minimumIntervalUs, preventing double-sleep stalls.
Cap = floor(hz - hz * hz / 3600)
Automatic cap applied only when VSync is enabled
